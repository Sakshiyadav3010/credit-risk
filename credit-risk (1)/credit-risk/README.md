# Credit risk: logistic regression vs. random forest

Predicts loan default on the UCI **German Credit** data and compares an interpretable linear model with a tree ensemble,
judged on precision, recall, F1, ROC-AUC, PR-AUC and **business cost**, not accuracy.

| Requirement | Where |
|---|---|
| Precision / recall / F1 / ROC-AUC (+ PR-AUC), not accuracy alone | notebook sections 4, 6 |
| Class imbalance addressed | stratified split, class weights, cost-based threshold (sections 3, 5) |
| Written argument: which error is worse | notebook section 7 |
| Feature importance in plain language | notebook section 8 and the generated summary |
| One-page non-technical summary | `reports/one_page_summary.md` (generated by the last notebook cell) |

## Run it
```bash
pip install -r requirements.txt
jupyter notebook notebooks/credit_risk.ipynb     # Run All
```
The data downloads automatically from OpenML (`credit-g`). Offline? Save it as `data/german_credit.csv` with a 0/1 `bad` column.
Run the notebook from the repo root (`jupyter notebook` there) so relative paths resolve.

Outputs land in `reports/`: figures, `test_results.csv`, `results.json`, and the summary with real numbers filled in.

## Design choices
* **Positive class = default.** Recall on defaulters is the headline metric.
* **Cost matrix 5:1** (approve a bad borrower : reject a good one), from the UCI docs. Edit `COST_FN` / `COST_FP`.
* **Threshold chosen on out-of-fold training predictions**, test set used once for the final report.
* **Permutation importance on original columns** makes both models comparable and easy to explain; odds ratios give direction.
* `DROP_SENSITIVE = True` removes age, personal status and foreign-worker status for a fairness-aware variant.

## Using Give Me Some Credit (built around `Data_Dictionary.xls`)
```bash
# download cs-training.csv from kaggle.com/c/GiveMeSomeCredit into data/
DATASET=gmsc jupyter notebook notebooks/credit_risk.ipynb
```
Target is `SeriousDlqin2yrs` (90+ days delinquent within 2 years). About 7% of rows are positive, so imbalance is far more severe than in German Credit.
Feature engineering follows the data dictionary and the data's known quirks:

| Issue | Handling |
|---|---|
| ~20% missing `MonthlyIncome`, some missing `NumberOfDependents` | median imputation inside the CV pipeline (no leakage) plus an `income_missing` flag |
| 96 / 98 placeholder codes in the past-due counts | set to missing, flagged with `late_code_flag` |
| `RevolvingUtilization` far above 1, `DebtRatio` in the thousands | clipped, plus `over_limit` and `debt_ratio_absurd` flags |
| `age` = 0 | treated as missing |
| Three separate lateness counts | combined into `total_past_due`, `any_90d_late` and a severity-weighted `weighted_lateness` |

GMSC ships no cost matrix, so the notebook keeps the 5:1 ratio as an explicit **assumption** (`COST_FN`, `COST_FP`) and says so in the summary.
Expect a much lower optimal threshold than on German Credit. Permutation importance is run on an 8,000-row subsample of the test set for speed.

`credit_risk.py` is the source of truth; `python build_notebook.py` regenerates the notebook from it.
